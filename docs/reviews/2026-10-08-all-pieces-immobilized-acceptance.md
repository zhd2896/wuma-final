# 全方无合法走法判负：实施与验收

日期：2026-10-08。代码位于当前项目目录、`codex/growth-feedback` 工作分支，尚未提交、推送或部署云端。

## 规则与完成范围

1. 完成本手合法移动，结算所有有效吃子及备用棋替换，再换到下一方。
2. 下一方所有在场棋子均无合法走法时，该方判负、另一方获胜，与在场棋子数量无关。
3. 还有任意合法走法则继续；备用棋不能直接投入棋盘解除围堵。单纯进入庙宇不判负。
4. 吃光对方优先返回原 `CAPTURE_ALL`；单子堵塞继续使用 `TEMPLE_TRAP` 或 `LONE_PIECE_IMMOBILIZED`，多子全部堵塞使用新原因 `ALL_PIECES_IMMOBILIZED`。

共享引擎已实施换手判定。本地、AI 和真正远程双人共用该结果；终局不再允许继续落子。历史、复盘、联机合同、对局提示、分析页和玩法讲解均接受并显示新原因。现有数据库字段可保存该字符串，不需要新增迁移。

旧历史首次生成复盘时，允许当前规则得到多子堵塞终局、原快照却仍 PLAYING 的精确差异；棋盘、备用数量与行棋方仍必须一致。原历史、后续认输结果不会重写，讲解标明按现行规则评价。已存在的异常进行中棋局不自动改写；直接送入 AI 的矛盾 PLAYING/无合法走法输入仍保留防御校验。本阶段未调整 AI 围堵策略。

## 实机验收与阶段判定

**代码实现完成；云端发布和真实页面验收尚未完成，暂不判定整个阶段验收完成。** 当前小程序开发配置指向云端后端，本地修改不会自动更新云端服务。

1. 将本阶段代码加入需要发布的版本，按现有云端部署步骤更新并重启后端，使 TypeScript 共享引擎和 Python 服务来自同一版本。本阶段无需新增数据库迁移。
2. 微信开发者工具打开当前项目目录，执行普通编译，使页面与合同更新生效。
3. 在隔离测试环境准备：A 占 P27/P28/P08/P05/P10/P15/P20/P25，B 占 P26/P29，轮到 A。A 走 P08→P03 后，应换到 B 并立即判 A 获胜，原因“所有棋子均无合法走法”。不要直接修改个人正式棋局来制作验收局面。
4. 分别核验本地、AI、联机：胜负弹窗及分析页正确；终局不能落子；退出重进、个人历史、复盘保留同一终局。
5. 联机用两台设备读取同一测试房间，核验双方胜负、版本、历史与复盘一致，断网后用原请求编号重试不增加棋步。
6. 部分棋子被堵但另有棋子可走，应继续对局；吃子后才全部被堵应判负；备用不足取消吃子后仍有合法走法应继续。
