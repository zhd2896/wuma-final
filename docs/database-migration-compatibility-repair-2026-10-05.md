# 棋局服务数据库兼容修复（2026-10-05）

## 原因

本机业务 MySQL 已启动，后端 `/health`、`/ready` 返回成功，但创建棋局及查询历史返回 `DATABASE_UNAVAILABLE`。业务库已应用 `codex/wechat-login` 分支的 `0011_wechat_auth_sessions`；主分支只包含对局操作迁移，Alembic 报 `Can't locate revision identified by '0011_wechat_auth_sessions'`，升级未执行。PowerShell 随后仍继续启动后端，新模型查询业务库缺少的 `games.ply_count` 等字段，导致棋局相关接口报错。

## 修复

- 从既有分支恢复 `0011_wechat_auth_sessions`，保留原版本号、父版本、字段、索引和外键；建表字符集与 0001 一致。
- 新增空操作合并节点 `0014_merge_auth_operations`，父节点为 `0013_remote_undo_revert_count` 与 `0011_wechat_auth_sessions`。原微信分支只补齐对局操作迁移，原对局分支只补齐会话迁移；全新库也有唯一 head。没有通过修改版本记录跳过迁移。
- 升级前完成本机备份，将备份恢复到独立临时实例验证升级，并对原有字段的每条记录比较 SHA256。随后升级实际 `wuma` 业务库，并再次检查数据一致。
- 启动说明增加迁移退出码检查，失败时停止，不继续启动 API。当前应用身份仍为匿名设备账号；此次恢复会话表迁移用于兼容已有数据库。
