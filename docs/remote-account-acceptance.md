# 联机账号归属验收（阶段二）

## 已实现行为

- 建房、邀请码加入、公开匹配在生产鉴权模式下绑定当前账号；换设备 ID 不能加入自己房间，匹配跳过本人房间。
- 房间查询、合法走法、落子、取消、认输、悔棋申请与处理、复盘都校验账号与令牌席位。写事务再次锁定有效账号和席位，拒绝账号迁移后仍在途的旧账号写入。复盘分析完成后的落库事务同样重新验证账号、令牌与本人席位；缓存复盘及回放查询完成后再次校验权限。
- `POST /api/v1/remote/rooms/{game_id}/recover` 仅允许已归属参与者恢复自己的席位并轮换令牌。`POST .../claim` 必须同时有当前账号与原始 `X-Room-Token`，不能凭设备 ID、邀请码或棋局 ID 认领。
- 微信账号合并迁移两个参与者字段；源账号和目标账号已占同局两席时返回 `REMOTE_ACCOUNT_CONFLICT`，整笔合并回滚并保留原账号。
- 两位参与者的云端分页历史返回 `REMOTE` 与各自 `seat`；他人无记录。复盘可用状态与复盘数量按本人席位计算，云端总局数包含联机，AI 胜负含义不变，另有 `remoteGames` / `remoteWins` / `remoteLosses`。
- 取消或到期的未开始房间不再显示为进行中，不计入云端对局。云端记录覆盖同 ID 的旧本机快照，保留纯本机记录作为离线与旧房间的入口。
- 客户端没有令牌时可凭登录账号恢复在线对局和终局复盘；旧房间有原令牌时显式认领，无资格时保留错误。有效的已绑定席位令牌不会因每次恢复而重复轮换。初次账号恢复网络失败时，页面保留棋局 ID，刷新重试可重新恢复。
- 显式 `require_auth=False` 的旧引擎测试路径继续可用。

## 真实两设备待验收

代码与自动化验证不等同于真机验收。部署后用两个独立微信账号 A/B：A 建房、B 加入并落子；第三账号不能查看或操作；A 在第二台无本机令牌的设备登录同一微信账号，从云端恢复自己的 A 席位；原设备旧令牌失效，B 的席位不受影响；完成对局后双方历史显示终局并分别进入本人复盘。微信真实网络、设备存储、授权环境、后台切换与断线恢复仍须按此流程验收。
