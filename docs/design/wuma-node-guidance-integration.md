# 点位编号与讲解联动实施记录

日期：2026-10-05。

## 已实现

- 玩法讲解新增 P01—P29 编号对照图，点击可放大，图示在本地分包内，可离线查看。
- 主盘从上到下、每行从左到右编号；P13 是中央，P03 是主盘的庙宇入口。庙内四点为 P26 左翼、P27 中间、P28 右翼、P29 宝顶。
- 本地、AI、真正远程双人对局设置新增“显示点位编号”，默认关闭；保存后沿用本机选择，旧设置中的其他选项保留。
- 复盘、独立教练、独立分析默认显示编号。文字增加位置说明，如“P07（第2行第2列）”。
- 教练二级提示标记关键点，三级提示展示推荐路线；收起、切换提示或更新棋局会清除旧标记。
- 分析页点击候选走法可查看对应路线，点击最佳推荐可恢复最佳路线。
- 复盘显示对应棋步的真实落子前局面，支持实际路线、最佳路线切换，同时展示当时双方备用棋数量。

## 数据来源与兼容

棋盘编号沿用项目现有节点 ID。编号图由 `miniprogram/mock/game.ts` 的节点坐标与连线生成，导出的几何数据保存在 `wuma-node-geometry.json`，1200×1200 图保存在 `wuma-node-reference.png`，同一文件复制到讲解分包。

后端复盘响应新增 `stateBefore`，从已有有效棋步快照关联，校验棋步 ID、手数、玩家、走法。已有复盘读取时同样补齐，已撤销棋步不能成为有效快照。不增加数据库字段，无需执行数据库迁移。路线预览不会落子、消耗备用棋或改写历史。

如果后端尚未更新，复盘保留文字和点位图入口，不以当前棋盘伪造旧局面。

## 启用与人工验收

1. 在原后端终端按 Ctrl+C，然后使用原数据库环境配置重新启动：
   ```powershell
   .\backend\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
   ```
   如果换了终端，请按原启动流程重新设置数据库参数。无需清空小程序缓存或历史，也无需数据库迁移。
2. 微信开发者工具重新编译项目。从首页进入“玩法讲解”，检查 29 点图，点击两张图分别放大；P03 应属于主盘，庙内只有 P26—P29。
3. 本地、AI、真正远程双人页面打开设置，开启编号，检查棋子遮挡、点击落子和庙内点位；关闭后编号消失。退出重进检查选项保存，其他设置应保持原选择。
4. 独立教练绑定一局真实棋局，依次展开二级、三级提示，检查关键点和箭头与文字一致；收起提示或棋局更新后旧标记应清除。
5. 分析页在候选走法之间切换，检查文字与箭头对应，棋子位置及备用数量不变；点击最佳推荐恢复其路线。
6. 从真实历史进入复盘，选择不同棋步，切换实际/最佳路线。棋盘应为该手落子前局面，起点有棋子，不能直接复用终局局面；有悔棋的对局应展示最终有效棋步。
7. 真机检查点位标签字号、棋子遮挡、起点/终点区分、放大手势及点击反馈。
