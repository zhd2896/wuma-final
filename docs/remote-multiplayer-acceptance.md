# 远程双人阶段验收记录

日期：2026-09-28

## 阶段目标

两台设备分别持有 A/B 席位凭证，在同一个服务器棋局中轮流落子；支持私人建房、邀请码加入、公开匹配、等待/取消、同步与本机重连。本阶段使用用户选择的设备房间凭证，不要求微信登录。

## 已实现

- 新增 `REMOTE` 房间与 `0009_remote_rooms` 迁移：独立 A/B 令牌只在签发时返回，数据库保存 SHA-256 摘要；邀请码唯一且等待 30 分钟后不可加入。
- 后端支持建房、加入、公开匹配、取消等待、带令牌读取房间/合法走法/提交落子。MySQL 使用房间行锁、棋局版本比较、棋步请求 ID 唯一约束和公开匹配数据库锁。第三人加入、同一设备自加入、错席落子和过期版本会被拒绝；重复请求返回已保存棋步。
- 普通棋局读取、合法走法、落子、局面分析和复盘接口拒绝 `REMOTE`，不能绕过房间席位规则。棋规与胜负继续由现有 TypeScript 引擎判定。
- 首页“远程双人”进入独立页面。页面提供建房、匹配、输入/复制/分享房间码、等待、取消、棋盘、每 3 秒刷新、手动刷新、同请求编号重试及返回房间大厅。本机保存每局席位凭证和最近活动房间，可从历史恢复进行中或已结束的棋局。旧服务器 `LOCAL` 同设备对局仅作历史兼容。

## 尚未满足的验收条件

1. **MySQL 真实持久化和并发匹配**：已在 `backend/tests/test_mysql_persistence.py` 写入联机持久化、服务重启恢复、重复请求与同时匹配测试，但本机未设置 `WUMA_TEST_DATABASE_URL`，也没有 Docker 命令。必须在已经升级到迁移 `0009_remote_rooms`、库名以 `_test` 结尾的独立 MySQL 数据库运行；不得用开发/生产库替代。
2. **两台真机端到端**：本机未监听微信开发者工具自动化端口 `9420`，仅有本机 API `127.0.0.1:8000`；小程序 `test` / `production` API 地址仍为空。应将测试后端部署到两台设备可访问的 HTTPS 地址，并配置微信合法 request 域名后，实测私人建房加入、公开匹配、双方轮流落子、断网重连、重开恢复、第三人拒绝和终局一致。
3. **凭证边界**：本阶段令牌仅保存在本机。清除本机数据后无法找回席位；账号登录和跨设备找回属于后续身份阶段。联机终局目前可从历史查看终局棋盘，复盘接入尚未纳入本阶段。
