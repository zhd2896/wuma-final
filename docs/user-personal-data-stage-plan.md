# 用户与个人数据阶段实施方案（2026-09-28）

## 决策与边界

用户选择先使用匿名设备账号。首次联网使用服务器签发的随机设备凭证创建 `users` 记录，凭证留在小程序本机存储；同机重开沿用身份。清除小程序数据后无法找回匿名账号。旧的 `user_id = NULL` 棋局、训练记录不自动认领。远程双人阶段暂缓，现有房间席位凭证继续独立工作。

## 实施

1. 后端新增设备注册、凭证鉴权和 `/api/v1/me` 个人资料接口。只存储设备凭证的 SHA-256 摘要，接口只在注册时返回原凭证；保护棋局、分析、教练、复盘、训练接口。
2. 新棋局与答题记录原子绑定用户；训练题和答题结果按来源棋局归属校验。个人棋局列表用不可变的 `(created_at, id)` 游标分页，统计只计算本人数据。
3. 小程序 API 客户端自动取得并附加本机凭证。历史页合并本人服务器棋局与本机离线棋局，个人中心显示真实统计和明确的数据不足状态。
4. 通过两个账号的越权、重启恢复、分页和统计测试；执行前端类型检查与安全的内存后端测试。MySQL 只在专用隔离测试库验证，不触碰日常数据库。

## 验收口径

无凭证或错误凭证不得读取个人数据。甲账号不得读取、落子、分析、复盘、训练乙账号的棋局。新账号统计为零；本人对局及答题后数据可重读且分页不重漏。真机与隔离 MySQL 验证作为阶段最终验收门槛，缺失时明确标记未验收。
