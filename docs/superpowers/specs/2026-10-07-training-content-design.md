# 分主题训练题与试玩校准设计

用户要求补充入门、进阶题，按吃子、防守、孤棋组织并校准难度。本次在既有精选训练流程内完成，不新增独立玩法。

- 保留 v1 三道复杂题的 ID、内容和个人完成记录。增加 v2 教学题，每个主题至少两道入门、两道进阶题，所有局面与答案由正式规则引擎验证。
- 入门和进阶是教学分级，不再由走法数量单独决定。复杂旧题仍显示引擎估计。主题筛选与难度、进度筛选可组合，分页与总数一致；列表先展示入门题。
- 新题说明包含训练目标，答案后显示解题要点；答题前不能泄漏最佳走法。吃子、防守、孤棋标签显示中文。
- 正式训练答题记录用于试玩校准：每题每账号只取首次合法、完成评分的答题，重复答题、请求重试和无账号记录不增加样本。至少 20 个账号才形成难度建议；首次正确率至少 75% 建议入门、至少 40% 建议进阶，否则建议复杂。
- 试玩难度建议与教学等级分别展示，课程分级与筛选保持稳定。样本不足明确标为待试玩校准。校准仅返回汇总，不返回玩家身份，不影响个人进度及评分。
- 程序执行真实引擎走棋、逐题提交正确与较差答案并生成验证报告；这验证解法与程序流程，不宣称真人已试玩。真实账号样本可以在后续使用中形成校准建议。
- MySQL 使用现有 JSON 与答题记录字段，无额外迁移。旧精选题无教学说明字段时保持兼容。

相比仅增加随机局面或直接把候选数少的题称为入门，这一设计优先教学目标、题目有效性和真实使用结果。自动改变教学分级会使课程和筛选随答题波动，故通过独立建议展示校准结果。
