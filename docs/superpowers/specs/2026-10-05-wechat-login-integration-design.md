# 微信登录集成设计

用户要求现在实现微信登录；沿用已确认的独立登录页和服务端微信认证设计，并修复本次分支审查问题。

## 方案与建议

采用点击按钮的微信登录。`wx.login` 获取临时 code，后端使用 AppID/AppSecret 换取真实身份并返回随机应用会话；前端只保存会话与到期时间。其他方案为只在云端功能请求时登录，或继续匿名设备账号；前者需要改变既有入口设计，后者不能实现微信身份跨设备恢复，所以本次继续已批准的独立登录方案。

有效会话可直接进入首页；失效或缺少会话进入登录页，不自动重放业务写入。个人中心退出仅清除本机应用会话，保留历史。头像和昵称不作为身份依据，本次不新增采集流程。

## 数据与集成

复用 `codex/wechat-login@ed18a39` 已有认证、账号升级或合并、会话持久化及界面代码。以当前 main 和未提交的点位讲解功能为实施基线，保留棋局操作、远程席位权限、编号设置、真实复盘快照。保留 main 的 utf8mb4 会话表迁移及唯一 head `0014_merge_auth_operations`。

旧匿名令牌只用于一次账号归属迁移；不认领无归属棋局。旧请求在新会话建立后返回 401，只结束旧请求，不能删除新会话或跳转当前页面。确实失效时返回登录页，保持原注册页面及查询参数。

玩法讲解属于静态内容，明确允许无会话访问。登录页提供玩法讲解入口，讲解页“开始 AI 对弈”仍需登录。登录返回路由只允许注册主页面与讲解分包路径，不开放任意 URL。

## 验证与启用

对局操作 E2E 脚本改为验证并注入微信会话，保存和恢复原会话，不改变隔离数据库及 API 检查。相关页面测试统一使用真实会话形状。

执行前端、后端完整回归、类型和页面检查；独立 MySQL 测试实例验证迁移、认证、并发与账号迁移。真实微信验证需要用户在后端填写 AppSecret，不能将密钥写入前端、Git或输出。无需读取当前私密配置或停止现有业务服务。

阶段分开判定：代码与隔离测试通过后报告代码完成；真实微信、开发者工具和跨设备测试通过后才报告整体验收完成。实现存放独立目录，未经用户要求不推送或合并 main。
