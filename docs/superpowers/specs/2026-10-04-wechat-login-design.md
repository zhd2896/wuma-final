# 微信小程序登录设计

用户已于本次对话批准微信登录及匿名数据迁移方案。

小程序 wx.login 获取一次性 code，POST /api/v1/auth/wechat 交给后端。后端使用环境变量 WECHAT_APP_ID、WECHAT_APP_SECRET 调用微信 jscode2session；前端提交的 OpenID 不作为身份依据。微信外部身份使用 AppID + OpenID 的 SHA-256 摘要，避免 MySQL 默认排序规则混淆大小写，沿用 users 主键及现有个人权限检查。微信 session_key 不下发、不持久化。

新增 auth_sessions 表保存随机 256 位令牌的 SHA-256 摘要、用户 ID 和 UTC 到期时间，默认 7 天。支持不同设备各自登录，同一微信用户拥有同一 users.id。生产小程序不再创建匿名账号；旧设备接口保留用于兼容迁移。

首次登录可附带旧匿名 device_token。事务中仅迁移 external_user_id 为 device: 开头的账号；不存在微信账号时直接升级原账号以保留主键，否则将 games.user_id 与 training_records.user_id 转到微信账号，并撤销匿名凭证。NULL 归属不认领，其他微信账号的数据不能迁移。重复提交过期旧凭证不会重复迁移。并发唯一键冲突重试事务，避免重复微信用户。

小程序按 API 环境保存令牌及 expiresAt，并合并并发登录。令牌过期重新 wx.login；收到 AUTH_INVALID 或 AUTH_REQUIRED 时重新登录并仅重试一次原业务请求。网络、403、游戏冲突不自动重试。登录成功保存新凭证后删除旧匿名凭证；失败保留旧凭证方便再次迁移。个人页措辞改为微信棋手。

验证覆盖成功/失败、跨设备同用户、不同用户隔离、匿名棋局与训练迁移、旧凭证撤销、期限到期、微信网络错误、登录并发合并及失效恢复。真实微信需要配置后台凭证、HTTPS request 合法域名并真机验证；本地测试不调用真实微信。专用 MySQL 测试库未配置时只生成迁移和集成测试，不触碰日常库。


审查补充：建局及训练答题的存储事务先锁定用户行并确认 external_user_id 未被清空。迁移先锁同一用户，因此迁移前认证、迁移后才写入的旧来源请求返回 AUTH_INVALID；小程序重新微信登录后仅重试一次，不产生失联记录。内存存储在目录锁内检查已合并用户集合。
