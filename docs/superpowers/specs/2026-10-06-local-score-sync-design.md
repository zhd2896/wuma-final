# 阶段五：本地完整棋谱与云端同步

## 目标与边界

新本地棋局逐手保存完整有效棋谱，悔棋后截掉有效分支，认输作为终局事件保存；关闭重开后仍能恢复。登录联网后可把棋谱同步成当前用户拥有的服务器 `LOCAL` 棋局，进入现有历史、复盘和训练链路。

采用客户端保存初始先手、有序落子与终局事件，服务端重演验证的方案。不能直接信任客户端快照、胜方或评分；不能用只有最后快照的旧记录伪造完整棋谱。

## 本机数据与兼容

本机历史增加带版本的初始信息和有效棋步列表，保留当前快照与既有最后一步/手数。新局从初始化开始具有完整棋谱；每次成功落子追加，悔棋移除对应有效棋步并恢复状态，认输保留棋谱并记录认输方。写存档时复制数据，避免后续 UI 或棋盘引用修改历史。

旧存档仍可续局、查看终局和使用已有可撤销帧；没有完整前缀的记录标明无法同步，用户可新开完整棋局，不能补造以前的落子。

## 服务端导入

新增已认证用户可调用的本地棋谱导入接口，接受客户端棋局 ID、先手、完整有序棋步与可空认输方。限制 ID、列表长度及节点参数。逐步通过唯一引擎执行，每手需合法，终局后不得追加；认输只允许未自然结束的局面，并由当前行动方发起。结果使用服务端重演得到的状态。

幂等键以当前用户和客户端棋局 ID 为范围，保存请求摘要；相同请求返回同一局，不同请求重用同一键返回冲突。账号合并须保持导入归属与幂等行为。创建棋局、棋步、终局事件和导入键在同一事务中完成；异常不留下半局。

客户端 ID 的大小写语义在内存与 MySQL 一致，不能由数据库默认排序规则默默合并两个不同标识。

合并两账号若已有相同客户端棋局 ID 指向不同云端棋局，明确返回导入归属冲突并原子保留原账号，不能删除棋局或悄悄覆盖链接。导入保存与合并沿用一致的账号锁顺序，已退休账号的在途请求不能创建新棋局。

第一版以显式同步为入口。同步中的记录不能继续本地修改；同步成功保存云端 ID，后续打开/续局转到该云端棋局，防止离线存档与服务器棋谱继续分叉。同步失败不清除存档。已结束记录同步后直接可复盘；未结束记录同步后由既有云端本地双人控制器继续。

网络失败或退出造成结果未确认时，冻结的上传载荷和待确认标记必须持久化，重开后只以原载荷重试，不能一边继续修改本机棋谱一边重用同一幂等键。同步链接的云端读取始终由服务器验证当前登录账号，不能把本机“已同步”标记当作云端访问权限。

待确认同步还需保存发起时的账号 ID 与 API 目标；换账号或目标地址后不能自动以另一身份重发未知结果的请求。本人重新登录可用新的会话令牌重试原请求，不把令牌本身写入本地棋谱。

## 前端

历史本地记录提供“同步棋谱”，显示同步中、失败重试、缺完整棋谱的解释。云端链接记录与个人云端列表去重，打开同步终局使用服务器 ID。不得把旧本地 ID 传给复盘接口。网络重试沿用原客户端棋局 ID和原载荷。

## 验收

本地走多手、撤销并换分支、重开小程序后有效棋谱一致；自然终局和认输同步结果正确；重复同步只保存一局；篡改节点、非法回合、终局后棋步、请求号与载荷冲突被拒绝；私有导入和读取按账号隔离；中途同步后续局只修改云端；旧快照仍可使用且不伪造棋谱。真实 MySQL事务/幂等与前端行为测试通过后进入下一阶段。
