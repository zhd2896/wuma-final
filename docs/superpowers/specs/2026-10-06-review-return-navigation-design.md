# 复盘返回导航设计（2026-10-06）

本设计在用户已授权的逐阶段完善范围内执行，由主任务审查，沿用 `codex/staged-completion`，不自动提交。

## 证据与根因

`review.back()` 仅调用 `wx.navigateBack({ delta: 1 })`。复盘可在登录后的 `reLaunch` 或直接进入时成为唯一页面，此时没有上一页；导航失败回调也没有恢复处理。这两条缺口可用页面行为测试重现。

2026-10-05 报告中的开发者工具问题还包含成功回调后页面栈未变和退出首页超时。现有日志不足以证明同一根因，本修复不能声称解决该环境问题。

## 方案与范围

1. 推荐：有上一页时保持 `navigateBack`；无上一页或失败时进入 `history?filter=reviewable`，复用现有会话检查和登录跳转。来源页及其状态在正常返回时保持。
2. 始终重启到历史页会丢失正常返回游戏和历史筛选的上下文，不采用。
3. 按来源参数重建上一页需要额外入口协议，也不能保留现有页面实例，不采用。

只改复盘页返回处理，不改悔棋、认输、设置和其他页面导航。回退时有有效微信会话才允许直接进入历史页，否则 `showLogin` 保存历史页为登录后目的地。`navigateBack` 同步抛错也按失败处理。没有定时器或对成功回调的猜测性超时重试。

## 验收

页面行为测试覆盖历史、普通游戏和联机来源的正常返回；空栈/单页；导航失败与同步抛错；缺失、过期会话的登录落点。再跑鉴权、规则返回、现有复盘测试以及前端全量、类型、页面组件检查。
