# 阶段九：个人资料与发布检查

## 个人资料

个人页支持用户主动编辑昵称及选择内置棋子头像，不读取或假称取得微信昵称头像。昵称去除首尾空白后长度 1～24 个字符，拒绝控制字符；头像仅接受版本化预置枚举，页面用现有棋子样式显示，不存任意远程 URL。采用当前 API 客户端支持的 POST `/api/v1/me/profile` 与严格请求模型。

更新只针对当前有效账号，数据库事务再次验证账号有效性。用户资料持久化，重登或换设备保留；微信登录不得覆盖已编辑昵称。账号合并保留已有目标账号资料，无已有微信目标时保留来源的自定义资料。头像默认值可兼容旧数据。失败保留编辑草稿与明确错误，成功更新展示；退出登录与加载代次隔离，不把旧账号结果显示到新账号。

登录页对已经存在的双席位合并冲突、后续本地棋谱导入编号合并冲突显示明确原因，保留本机记录及迁移凭据，不把确定的合并冲突显示成网络暂时不可用；不自动删除或跳过用户记录。

## 发布配置

用户已明确“暂未部署”。保留开发地址及未填写的体验版、正式版地址，提供可审查的构建时公开地址配置方式和 `check:release` 命令，不生成假域名。

检查指定 trial/release 目标：对应地址必须非空 HTTPS，禁止 localhost、回环、本地私有 IP、认证信息、片段和非法 URL；微信 AppID 不能是占位值。地址可包含部署前缀路径，客户端拼接不得丢失。开发检查照常允许本机地址。失败明确说明缺少的公开配置，不输出密钥。

API 根地址不接受查询参数，避免接口路径被拼进查询字符串；检查失败不能回显含认证信息的原始地址。

客户端在未配置发布地址时安全返回登录页，显示“服务暂未开放，请稍后再试”并停止发起请求，不能把空地址拼接发送，也不向普通用户暴露配置文件或密钥细节。

补充部署指南：后端 HTTPS、微信 request 合法域名、AppID/服务端 WeChat 配置、数据库迁移、体验版及正式版地址对应关系、登录及两账号联机验收步骤。不读取或修改本地密钥，不调用微信发布接口，不自动部署。

## 展示与总体验证

移除未使用的 demoMode 与项目元数据中旧的 UI 演示描述，保留实际棋盘几何与资源。修正旧审计文档为历史快照并链接当前进度，清楚区分已实现代码与未部署的真实环境验收。

复查发现普通本地/云端双人页的“提示”仍只弹出“暂不提供”，另有不可达的演示提示面板。将这两种模式的提示接到已有真实局面分析入口，以当前棋局实际合法候选走法提供建议；AI 模式保留三级教练。移除不可达演示分支及面板引用，验证各模式点击路由与缺棋局时的明确反馈，不用静态文案冒充引擎建议。

验证全部前端测试、类型及页面检查，全部后端测试（真实隔离 MySQL 与新空库迁移），审查各阶段代码。运行发布检查应在未配置 trial/release 时按预期失败，不能把该失败描述为已发布或业务测试失败。用有效公开测试输入验证检查可通过，但不保存为真实发布地址。

总体验证复查普通棋局及训练写入在账号合并期间的归属检查；仅按可复现缺口补回归和事务校验，使已退休账号的在途请求不能继续写入迁移后的资源。保持已有接口和显式无鉴权引擎测试兼容，不进行无关重构。

## 验收

本人可修改资料，陌生人不能修改，非法昵称/头像拒绝、退休账号在途更新拒绝、重登不丢自定义值、合并选择符合上述规则；前端保存与失败重试通过。发布检查覆盖空配置、非 HTTPS、回环/私有地址及有效地址，用户收到真实配置待办与已完成阶段清单。
